Class 1

Introduction to Generative AI

19 concepts

Generative AI (GenAI)

AI models designed to generate original content such as text, images, audio, video, or code from patterns learned from large-scale training data.

Predictive AI

AI focused on predicting outcomes, classifying information, detecting anomalies, or forecasting rather than creating new content.

Symbolic AI

An early AI approach that represents knowledge with symbols and uses explicit, human-written rules and logic to reason.

Limitations of Symbolic AI

Rule-based systems are difficult to scale to complex real-world situations, depend on manually encoded knowledge, and are brittle when they encounter situations not covered by their rules.

Moravec's Paradox

The observation that tasks humans regard as intellectually difficult, such as formal reasoning, can be relatively easy for computers, while perception and sensorimotor skills that humans perform effortlessly can be computationally difficult.

Statistical Machine Learning

An approach in which models learn patterns and relationships from training data rather than relying on explicitly programmed rules.

Deep Learning

Machine learning based on multilayer neural networks that learn increasingly useful representations from large amounts of data.

Foundation Model (FM)

A model pretrained on broad data at scale that can be adapted to many downstream tasks rather than being built for only one narrow task.

Large Language Model (LLM)

A large neural language model trained on extensive text data to learn language patterns and generate or process language.

Pre-training

Large-scale initial training through which a model learns broad patterns and knowledge from massive datasets before task-specific adaptation.

Why Pre-training Reduces Deployment Cost

A single pretrained foundation model can be reused and adapted for many tasks, avoiding the need to build and train a separate model from scratch for every application.

Transformer

A neural architecture based on attention that can efficiently model relationships among tokens, including long-range dependencies.

Generative AI as a New Era

Modern GenAI moves beyond prediction and classification to creating new content and supporting natural-language interaction, allowing general-purpose pretrained models to be adapted across many tasks.

Natural-Language Interface

Users can interact with GenAI in everyday language instead of needing specialized programming or technical interfaces, lowering barriers to AI use.

Prompt Engineering

Designing and refining the instructions supplied to a pretrained model to guide its output without changing the model's underlying parameters.

Fine-Tuning

Further training a pretrained model on domain- or task-specific data to adapt its behavior and improve performance for a particular use case.

Retrieval-Augmented Generation (RAG)

Combining an LLM with external information retrieval so responses can use relevant current or domain-specific information rather than relying only on knowledge encoded in model parameters.

Agentic Systems

AI systems that extend generation with capabilities such as reasoning, planning, memory, tool use, feedback, and autonomous action toward a goal.

Business Transformation from GenAI

GenAI can automate or augment content creation, customer support, analysis, knowledge work, and decision support while making sophisticated AI capabilities accessible through natural language.

Class 2

Architecture of Generative AI

21 concepts

Tokenization

Breaking text into smaller units called tokens so the model can process it.

Embedding

Converting a token or text item into a dense numerical vector representation that captures aspects of its meaning.

Semantic Space

A vector space in which representations with similar meanings tend to be located closer together; distance therefore reflects semantic similarity.

Positional Encoding

Information added to token representations so a Transformer can represent the order or position of words in a sequence.

Self-Attention / Attention Mechanism

A mechanism that lets each token weigh the relevance of other tokens when constructing its representation, enabling the model to capture long-range dependencies.

Multi-Head Attention

Multiple attention operations performed in parallel so the model can capture different types of relationships among tokens.

Training

The phase in which model parameters are adjusted from data so the model learns patterns.

Inference

The phase in which an already-trained model applies learned patterns to new input to produce an output.

Diffusion Model

A generative model that learns to generate images or other data by learning how to reverse a gradual noising process.

Forward Diffusion Process

The training process that progressively adds noise to data until the original structure is obscured.

Reverse / Denoising Process

The learned process that gradually removes noise to reconstruct or generate a coherent sample.

Conditioning

Providing additional information, such as a text description, to guide the diffusion generation process toward a desired output.

Multimodal Model

A model that works across more than one modality, such as text and images, enabling tasks that connect language with visual or other forms of information.

Pretrained LLM

A language model after broad pretraining but before additional alignment for instruction-following and conversational behavior.

Instruction Fine-Tuning (IFT)

Training a pretrained model on instruction-response examples so it learns to understand and follow user requests and produce appropriate responses.

Human Preference Fine-Tuning

Further aligning model responses with human preferences by learning from human judgments about which responses are better.

RLHF

Reinforcement Learning from Human Feedback: human preference data is used to train a reward signal and improve the model toward responses humans prefer.

DPO

Direct Preference Optimization: a preference-learning approach that directly increases preference for chosen responses over rejected responses without the full intermediate reward-model process used in RLHF.

Benchmark

A standardized dataset or task set used to evaluate and compare model capabilities.

Enterprise Evaluation

Evaluation tailored to an organization's actual domain, use cases, risks, requirements, and performance criteria; public benchmarks alone may not reflect these production needs.

Choosing Architectures by Task

Transformers are appropriate for language understanding and text analysis; diffusion models are designed for image generation; multimodal models are useful when a task connects text with images or other modalities.

Class 3

Prompt Engineering Basics

16 concepts

Prompt Engineering

The skill of crafting clear text inputs (prompts) to guide GenAI models such as LLMs toward specific outputs. Because an LLM does not inherently understand a user's intentions, a well-designed prompt helps align the response with the desired outcome.

Four Core Elements of a good Prompt

The chapter identifies four elements that consistently help improve LLM performance: Specific Instruction, Context, Input Data, and Output Indicator. These elements are not mandatory in every prompt; they are components that can be combined as needed.

Specific Instruction

The command that specifies what the model needs to accomplish. Explicit instructions define the task and help the model produce an output aligned with the user's expectations.

Input Data

The specific content that the model will analyze. Defining the input precisely helps the model focus on relevant information and avoid unrelated details.

Output Indicator

The desired format or structure of the response. It tells the model how the answer should be presented, such as a certain number of items, percentages, a category, or an actionable recommendation.

Context

Background information that situates the task in a particular scenario and identifies relevant aspects for analysis. Context helps the model interpret the request appropriately.

Iterative Refinement

Prompt creation is an iterative process. The chapter describes a cycle of initial test, evaluation, refinement, and optimization: test a prompt, evaluate whether the response follows the instructions and context, revise unclear or insufficient parts, and repeat until the output consistently meets the objective.

Zero-Shot Prompting

Asking the model to perform a task without providing examples. The model relies on its pretrained knowledge to interpret the request and produce an answer.

Zero-Shot Limitation

Without examples, a model may interpret nuanced or context-specific requirements inconsistently, especially when the expected format, label meaning, or decision rule is not obvious.

Few-Shot Prompting

Providing a small number of examples in the prompt to demonstrate the desired pattern, format, interpretation, or reasoning approach before asking the model to handle a new case.

Purpose of Examples in Few-Shot Prompting

Examples help clarify task expectations and show the model the desired output pattern. They can increase the accuracy and consistency of responses when the required format or interpretation might otherwise be ambiguous.

Limits of Few-Shot Prompting

Few-shot examples provide only limited contextual depth. They may be inadequate for nuanced, dynamic, or complex multi-step situations, and the model may imitate patterns in examples rather than truly learn a new rule.

Role-Playing / Persona Prompting

Assigning the model a specific role or persona so that its response reflects a particular perspective, expertise, tone, or communication style. The chapter uses roles such as a customer support agent and a business consultant.

Advantage of Role-Playing

Role-playing helps the model generate responses that are more context-specific and appropriate to the assigned role, including differences in expertise, tone, and communication style.

Chain-of-Thought (CoT) Prompting

A technique designed to guide an LLM through a multi-step reasoning process. Instead of jumping directly to a conclusion, the model is encouraged to work through intermediate steps.

Few-Shot CoT

Provides worked examples that demonstrate the reasoning steps as well as the final answer. The examples show a reasoning structure that can be applied to similar tasks.

Class 4

Advanced Prompt Engineering & Reasoning

21 concepts

System Prompt

A broad directive that establishes the model's overall behavior and role. It can define tone, constraints, objectives, and interaction rules that should remain consistent across interactions.

User Prompt

A task-specific instruction supplied during an individual interaction. It communicates the immediate request the model should complete.

System Prompt vs. User Prompt

The system prompt establishes general behavior and persistent guidance, while the user prompt supplies the task-specific instruction. They work together: the system prompt creates consistency and the user prompt adapts the interaction to a particular need.

LLM Parameter Control

Inference-time model parameters can be adjusted to influence output style, creativity, diversity, structure, and length without changing the model's underlying knowledge.

Temperature

Controls randomness in token selection. Lower temperature emphasizes higher-probability tokens and produces more stable, deterministic, and focused output. Higher temperature increases variability and creativity.

Top-P

A cumulative-probability threshold that limits token selection to a set of the most probable candidate tokens. It provides another way to balance focused output with diversity.

Max Length

Defines the maximum number of tokens the model can generate and therefore places a boundary on response length.

Frequency Penalty

Discourages repeated words or tokens by increasing the penalty as they appear repeatedly. It is used to reduce repetitive phrasing.

Presence Penalty

Discourages reuse of information or ideas that have already appeared, encouraging the model to introduce new concepts and increase variety.

Tree-of-Thoughts (ToT)

A prompting technique that guides a model to systematically explore multiple possible reasoning paths. The model can compare alternatives and, when needed, backtrack rather than follow only one linear chain.

Self-Consistency

Generating multiple responses or reasoning paths to the same question and comparing them for consistency. Agreement across independent responses can increase confidence in the result.

Self-Refinement

The model first produces an answer, then evaluates or critiques that answer, identifies weaknesses, and revises it to improve the final response.

Self-Explanation

Prompting the model to explain its reasoning process. The explanation can make the reasoning more transparent and help expose inconsistencies or errors.

Emotional Amplification

Adding emotionally meaningful context to a prompt to improve the model's responsiveness to emotional or sensitive situations. The chapter discusses its usefulness in settings such as customer support, mental health, and social interaction.

Reasoning Model

A model designed to handle complex multi-step tasks by breaking a problem into smaller steps, evaluating intermediate reasoning, and constructing a structured solution.

Conventional LLM vs. Reasoning Model

The chapter contrasts conventional LLMs, which tend to produce direct responses based on learned language patterns, with reasoning models that explicitly decompose problems, work through intermediate steps, and provide more structured justification.

Step-by-Step Reasoning

Breaking a complex task into smaller logical steps makes the reasoning process more visible and checkable. This is the central advantage highlighted for reasoning-oriented approaches.

Chain-of-Thought for Complex Tasks

CoT is the chapter's technique for prompting explicit multi-step reasoning. It is appropriate when a task benefits from showing or following a sequence of reasoning steps, such as calculations or logical analysis.

CoT vs. Tree-of-Thoughts

CoT follows a step-by-step reasoning chain. ToT expands the process by exploring multiple possible reasoning paths, comparing them, and potentially backtracking.

CoT vs. Self-Consistency

CoT structures a reasoning path. Self-consistency generates multiple answers or reasoning paths and compares them to identify a consistent result.

Risks / Costs of Reasoning-Heavy Prompting

The chapter cautions that more elaborate reasoning is not always necessary. Reasoning-heavy prompting can require more computational resources and can produce unnecessary detail or complexity for simple tasks. Longer reasoning processes also create more intermediate steps in which mistakes may occur.

Class 5

Retrieval-Augmented Generation

22 concepts

Retrieval-Augmented Generation (RAG)

A system that combines retrieval of external information with an LLM so generation can be grounded in relevant retrieved context.

Why RAG

RAG addresses limitations of closed-book pretrained models by providing access to current, domain-specific, or proprietary information at query time and by grounding responses in retrieved sources.

Closed-Book LLM

An LLM that answers primarily from knowledge encoded in its parameters, without retrieving external information at query time.

Open-Book Analogy

RAG is analogous to an open-book exam because the model can retrieve relevant external material before producing its answer.

Knowledge Base

The external collection of documents or information that a RAG system searches.

RAG Pipeline

User query -> retrieval/search -> relevant documents -> retrieved context combined with the query -> LLM -> response.

Knowledge-Base Preparation

Documents are split into chunks, transformed into embeddings, and stored/indexed in a vector database for later retrieval.

Chunking

Dividing documents into smaller pieces that can be embedded, stored, and retrieved independently.

Embedding

A dense, high-dimensional numerical vector representing semantic information in a word, sentence, paragraph, or document.

Semantic Similarity

Similarity in meaning represented by proximity of vectors in embedding space; closer embeddings indicate more semantically related content.

Vector Database

A database optimized to store, index, and retrieve embedding vectors efficiently.

Similarity Search

Searching for stored vectors closest to a query vector in semantic space in order to retrieve meaningfully related content.

Retrieval

The stage that identifies information in the knowledge base relevant to the user's query.

Augmentation

Adding retrieved information to the context or prompt supplied to the LLM.

Generation

Using the original query together with retrieved context to produce the final response.

Keyword Search

Retrieval based mainly on lexical or exact term matching.

Semantic / Vector Search

Retrieval based on embedding similarity, allowing semantically related content to be found even without identical keywords.

Hybrid Search

Combining keyword-based and semantic/vector-based retrieval to benefit from both exact matching and semantic similarity.

Reranking

Reordering initially retrieved documents with an additional relevance method so the most useful results are prioritized.

RAG for Domain-Specific Knowledge

Organizations can update an external knowledge base with specialized or changing information and retrieve it at query time without retraining the LLM each time the knowledge changes.

RAG Limitation

RAG performance depends on the quality, freshness, chunking, indexing, and retrieval of the knowledge base; poor retrieval can still lead to incomplete or inaccurate answers.

Class 6

RAG Techniques & Evaluation

36 concepts

Three RAG Stages

RAG challenges and improvements can be organized into pre-retrieval, retrieval, and post-retrieval stages.

Pre-Retrieval

Preparation of data, document organization, chunking, metadata, and queries before the system performs retrieval.

Retrieval

The stage in which the system searches for and retrieves information relevant to the user's query.

Post-Retrieval

The stage in which retrieved information is prioritized, filtered, compressed, validated, and prepared for generation.

Data Quality Management

Maintaining accurate, relevant, fresh, well-organized knowledge-base content so retrieval is based on reliable information.

Fixed-Size Chunking

Splitting a document into chunks of a predetermined length.

Overlapping Chunking

Creating chunks that share some text at their boundaries to reduce loss of context across chunk breaks.

Semantic-Aware Chunking

Choosing chunk boundaries based on semantic or document structure rather than only a fixed token count.

Hierarchical Chunking

Maintaining relationships between small chunks and larger parent sections/documents so retrieval can combine precise matches with broader context.

Chunk Size Trade-Off

Chunks that are too large can dilute relevant information and reduce retrieval precision; chunks that are too small can fragment context and omit information needed to answer a question.

Query Rewriting

Reformulating a user's query into a form that is more effective for retrieval.

HyDE

Hypothetical Document Embeddings: the model generates a hypothetical document or answer for the query; that generated text is embedded and used to retrieve similar real documents.

RAG Fusion

Generating multiple related query variations, retrieving results for each, and combining/reranking the retrieval results to improve coverage and relevance.

Hybrid Search

Combining keyword retrieval with semantic/vector retrieval; this can recover both exact terminology and conceptually related documents, making retrieval more robust than relying on only one method.

Reranking

Reordering retrieved candidates according to estimated relevance so the strongest evidence is prioritized for the LLM.

Contextual Compression

Filtering, extracting, or summarizing retrieved passages so that only the most relevant content is passed to the LLM.

Specific Post-Retrieval Prompting

Explicit instructions telling the LLM how to use retrieved evidence, such as grounding its answer in the supplied context and avoiding unsupported claims.

Parent Document Retrieval

Retrieving a precise smaller chunk for matching while returning its larger parent section/document to provide the LLM with sufficient surrounding context.

Precision

The proportion of retrieved documents that are relevant: relevant retrieved items divided by all retrieved items.

Recall

The proportion of all relevant documents that the system successfully retrieves: relevant retrieved items divided by all relevant items.

Latency

The response time required to process a query.

Throughput

The number of queries a system can process over a given period.

Generation Quality

Quality of the generated response; the chapter mentions metrics such as ROUGE, BLEU, and BERTScore for comparing generated and reference text.

Faithfulness

Whether the generated answer is actually supported by the retrieved documents and whether citations correctly point to the supporting information.

Answer Relevancy

How relevant the generated answer is to the question.

RAGAS

A framework used to evaluate and diagnose RAG systems across retrieval and generation behavior.

Human Evaluation

Human judgment used for qualities such as factual accuracy, relevance, and clarity that automated metrics may not fully capture.

Why RAG Evaluation Is Harder

A RAG answer depends on multiple components - data preparation, retrieval, ranking, context construction, and generation - so evaluation must determine not only whether the final answer is good but also where errors originated.

Fluent but Factually Wrong Responses

Fluency alone is insufficient; when an answer reads well but is unsupported or incorrect, evaluation should focus on faithfulness/factual grounding and citation accuracy.
